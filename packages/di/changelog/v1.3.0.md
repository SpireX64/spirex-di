# SpireX/DI — v1.3.0 Change Log

v1.3.0 introduces **Asterisk Binding** — a wildcard name (`*`) that acts as a fallback for unknown or missing bindings. Combined with **Scope Allowed List**, **Per-binding Lifecycle Hooks** (`onActivated`, `onDispose`), and **Dispose Ordering**, this release gives developers fine-grained control over instance creation, teardown, and scope-level access restrictions.

## Asterisk Binding (`*`)

The `*` name creates a **fallback binding** — when an exact named or unnamed binding is not found, the container falls back to the `*` entry. This works for both named and unnamed lookups:

```ts
binder
    .bindInstance("apiUrl", "https://default.example.com", { name: "*" })
    .bindFactory("logger", factoryOf(Logger), { name: "*" });

// No exact match → falls back to "*"
container.get("logger");           // Logger instance from "*"
container.get("apiUrl", "custom"); // "https://default.example.com"
```

Asterisk aliases make an existing binding the default:

```ts
binder
    .bindFactory("service", factoryOf(Service), { lifecycle: "lazy" })
    .bindAlias("service", "service", { name: "*" });

container.get("service", "new") === container.get("service"); // true
```

An asterisk alias must reference an existing binding — it cannot create a fallback to a non-existent entry. If you need a fallback alias, create the asterisk binding explicitly first:

```ts
// (FAIL) Alias to a non-existent binding — fails at build time
binder.bindAlias("service", "serviceReal", { name: "*" }); // Error

// (OK) Explicit asterisk binding, then alias to it
binder
    .bindFactory("service", factoryOf(Service), { name: "*" })
    .bindAlias("service", "service", { name: "*" });
```

`getAll(type, "*")` returns every registered instance of that type, regardless of name — no more manual grouping with `bindAlias`:

```ts
binder
    .bindFactory("service", factoryOf(ServiceA), { name: "A" })
    .bindFactory("service", factoryOf(ServiceB), { name: "B" });

container.getAll("service", "*"); // [ServiceA, ServiceB]
```

Asterisk factories receive the originally requested name via `ctx.name`, enabling dynamic behaviour:

```ts
binder.bindFactory("gateway", (r, ctx) => {
    if (/^mock-/.test(ctx.name)) return new MockGateway();
    return new RealGateway(r.get("httpClient"));
}, { name: "*" });

container.get("gateway", "mock-tests");  // MockGateway
container.get("gateway");                // RealGateway
```

Multi-binding (`ifConflict: "append"`) is **forbidden** for `*` — fallback must be deterministic.

## Scope Allowed List

Restrict which types can be **directly** resolved from a scope via `allowedList`. Non-listed types throw for `get()`, `providerOf()`, `phantomOf()`; return `undefined` for `maybe()`; and `[]` for `getAll()`:

```ts
const cartScope = container.scope("cart", {
    allowedList: ["cartStore", "cartRouter"],
});

cartScope.get("cartStore");    // OK
cartScope.get("usersManager"); // Error: not accessible in scope "cart"
```

This restriction applies **only to direct resolution** — dependencies requested by factories during activation bypass the check.

## Per-binding `onActivated`

A lifecycle hook called immediately after a factory creates an instance, but **before** the `onActivated` middleware. Unlike middleware, it **cannot replace** the instance:

```ts
binder.bindFactory("httpClient", (r) => {
    const client = new HttpClient(r.get("apiHost"));
    client.setAuth(r.get("config").token);
    return client;
}, {
    lifecycle: "lazy",
    onActivated: (client) => client.init(),
});
```

## Per-binding `onDispose`

Attach cleanup logic directly to a binding without modifying the class. `onDispose` takes priority over `Symbol.dispose` and `.dispose()`:

```ts
binder.bindFactory("db", factoryOf(DatabaseConnection), {
    lifecycle: "scope",
    onDispose: (db) => db.close(),
});
```

The disposal protocol is: `onDispose` → `Symbol.dispose` → `.dispose()`. Applies to `"scope"`-lifecycle instances.

## Dispose Ordering

Control the order in which instances are cleaned up when a scope is disposed. Higher `disposeOrder` runs later:

```ts
binder
    .bindFactory("ws", factoryOf(WebSocket), { lifecycle: "scope", disposeOrder: 1 })
    .bindFactory("db", factoryOf(Database),   { lifecycle: "scope", disposeOrder: 10 });
// ws is disposed first, db second
```

Default `disposeOrder` is `0`.

## Optimizations

- `ID_SEP` (`"$"`) exported as a public constant.
- Fewer entry ids allocations by reusing computed IDs where possible.
- Removed `resolutionStack` and `activationStack` re-allocations.
- Replaced `apply`-based argument decomposition in middeware calls with direct arguments.
